# mihomo-tui 订阅管理与配置热加载 — 设计文档

日期：2026-10-24
状态：待批准

## 1. 意图与背景

mihomo-tui 目前是 mihomo 外部控制器的一个只读终端客户端（总览 / 代理 / 连接 / 日志四个标签页）。本设计的意图是把它扩展为可以**替代现有 GUI 客户端**（如 Clash Verge）的工具：

- TUI 负责订阅管理、配置生成与合并、以及通过控制器触发热加载；
- mihomo 内核进程保持外部（系统服务或用户自启），TUI 不管理其生命周期；
- 用户通过快捷键在多个订阅之间切换，代理列表支持并发测速。

## 2. 目标

1. **导入订阅链接**：自动识别格式（Clash/mihomo YAML、base64 分享链接列表、单条分享链接），产出导入报告（节点数、协议分布；不支持的协议明确列出，不静默丢弃）。
2. **多订阅管理与切换**：订阅可命名、列出、删除、切换；切换 = 与 base 合并生成新运行配置 + 通过控制器热加载。
3. **base 配置与订阅合并**：按配置块粒度 diff，冲突由用户逐块确认；每个订阅保存策略记忆（base 优先 / 订阅优先）作为下次预选；无差异时直接切换，不打扰。
4. **并发测速**：TUI 自己调度并发池；范围三档——单个节点、当前分组、当前订阅全部节点（跨分组去重）；结果实时回填、可中途取消、可按延迟排序。
5. **配置热加载**：TUI 内部改动直接生成并重载；磁盘文件被外部修改时防抖后进入待确认状态，diff 确认后才重载；重载后健康检查失败自动回滚。

## 3. 非目标（v1）

- 不管理 mihomo 进程：不启动、不停止、不守护、不安装服务。
- 不修改系统代理设置、不创建/销毁 TUN 设备（TUN 是否开启只是配置字段）。
- 不提供 base 配置或规则的编辑器 UI：`base.yaml` 由用户手工编辑，TUI 负责监听与热加载。
- 不内置 subconverter 之类的订阅转换服务。
- 只支持 mihomo 单内核，不考虑 Clash premium 或其他内核。

**反目标**：切换订阅不得在用户不知情的情况下改变规则 / DNS / TUN 等非节点行为——这类变更必须经过确认页。开发与测试期间不得影响本机网络（不启动 mihomo、不改系统代理、不访问真实订阅）。

## 4. 约束

- Rust edition 2024；沿用现有模块划分（`main.rs` 事件循环 / `app.rs` 状态 / `api.rs` 客户端 / `ui.rs` 渲染）与测试风格（单元测试 + `TestBackend` 渲染断言）；现有 56 个测试必须保持通过（本设计明确的行为变更所涉及的既有断言允许相应改写，如分组测速迁入并发池）。
- 新增第三方依赖需在设计计划中说明理由（预计至少需要：YAML 解析/序列化、文件监听）。
- 兼容目标：mihomo 1.19.x 外部控制器 API；控制器可能要求 Bearer secret。
- 所有网络交互（订阅下载、控制器调用）在测试中必须走本地 mock；文件操作用临时目录。
- 订阅 URL 可能含 token，落盘文件权限 0600。

## 5. 核心概念与数据模型

- **base 配置**：TUI 拥有的长期配置（端口、DNS、TUN、规则、模式等），用户可直接编辑文件。
- **订阅（Profile）**：一条订阅链接及其本地快照。字段：`id`、`name`、`url`、创建/更新时间、**策略记忆**（每个配置块记录上次选择的来源：base 或订阅）。
- **快照**：导入/更新时下载并解析的原始内容 + 解析结果（节点、分组、协议分布、导入报告）。**切换永远使用本地快照**，不联网、秒切。
- **运行配置（runtime）**：base 与所选订阅按确认结果合并生成的完整 mihomo 配置，写入 `runtime.yaml` 并通过控制器应用。

冲突解决记录粒度：**订阅 × 配置块 → 来源**。配置块清单（v1）：`proxies`、`proxy-groups`、`rules`、`dns`、`tun`、入站端口（mixed/http/socks/redir/tproxy）、`log-level`、`allow-lan`、`ipv6`、`mode`。不做逐行/逐字段 diff。

## 6. 功能行为

### 6.1 订阅导入与解析

- 输入嗅探三类：Clash/mihomo YAML；base64 编码的分享链接列表；单条分享链接（`vmess://`、`vless://`、`trojan://`、`hysteria2://`、`anytls://` 等）。
- v1 链接转换器协议清单：**VLESS、Hysteria2、VMess、AnyTLS、Trojan**。Clash/mihomo YAML 走原生解析，不受清单限制。清单外协议在导入报告中明确标注"不支持"，不阻断整个订阅。
- 导入时立即下载快照并落盘；网络失败则导入失败并提示。
- 导入报告内容：节点总数、协议分布、被跳过的节点及原因。

### 6.2 订阅切换（diff → 确认 → 热加载）

流程：选择订阅 → 与 base 按块 diff →

- **无差异**：直接生成运行配置并热加载，不弹确认。
- **有差异**：进入确认页，逐块展示差异摘要与来源选择；预选该订阅已保存的策略；用户可修改每块来源、可勾选"记住"（写入该订阅的策略记忆）；确认后生成并热加载。

切换入口：Subscriptions 页 `enter`；全局 `[` / `]` 循环切换上一个/下一个订阅（同样走确认流程）。

### 6.3 并发测速

- TUI 维护并发池（默认 8，可配置），对每个节点调用 `GET /proxies/{name}/delay`；不用 `GET /group/{name}/delay`（无法控制节奏与取消）。
- 三档触发：`t` 高亮单节点；`T` 当前分组全部成员；`A` 当前订阅全部节点（跨分组按名称去重）。现有 `T` 从 group 端点迁入并发池，`Command::TestGroup` 及其断言被池化测速取代。
- 测速请求按请求设置超时（`--timeout` + 余量），绕开现有 HTTP 客户端 10 秒总超时的截断。
- 每个结果实时回填延迟与颜色；`Esc` 取消未完成的；进行中显示进度（n/m）。
- 完成后可按延迟排序。
- 测速必须走现有 command/event 架构在后台任务执行，UI 不阻塞；单节点失败不影响其余。

### 6.4 配置生成与热加载

- 生成前本地校验：YAML 结构合法、`proxies` 非空、协议字段完整；**跨块引用完整性**——`proxy-groups` 成员与 `rules` 引用的策略名必须能落到 `proxies`/分组上。悬空引用在确认页对应块显示警告；生成时自动修补：分组中缺失的成员若存在于订阅节点则并入、否则剔除；引用缺失分组的规则剔除；每次修补都明确提示。健康检查 + 回滚仅作最后兜底。校验失败则不触碰控制器，toast 报错。
- 生成的 `runtime.yaml` 原子写入（临时文件 + rename），**包含当前连接使用的 `external-controller` 与 `secret`**（这样"把系统服务指向 runtime.yaml"才能持久化），权限 0600——代价是凭据多落一份盘，需写入用户文档。
- 应用方式：通过控制器重载。优先尝试 `PUT /configs` 携带内联 `payload`；若该端点在 mihomo 1.19 不接受 payload，则写文件传 `path`。建造者需在计划阶段对照 mihomo 源码/文档确认。
- 重载成功后 `GET /version` 健康检查；失败则**回滚**：重新提交上一份可用配置并 toast 报错；回滚也失败则进入现有 offline 状态。
- 切换会断开现有连接（mihomo 行为），UI 需提示；`/traffic`、`/logs` 流依赖现有自动重连机制。
- **已知限制（需写入用户文档）**：经控制器加载的配置不写回内核自己的启动文件，mihomo 重启后会回到其启动配置；用户可将系统服务指向 `runtime.yaml` 来持久化，后续版本再考虑引导。

### 6.5 外部文件修改

- 监听 `base.yaml` 与 `subscriptions/` 目录，防抖约 500ms（编辑器多次写入合并为一次）。
- 外部修改**不自动应用**：进入待确认状态，状态栏提示，展示与当前运行配置的 diff 确认页；确认后才生成并重载。
- 订阅快照文件被外部改动视为该订阅内容更新，同样走 diff。

### 6.6 界面与交互

- 新增第 5 个标签页 **Subscriptions**：`a` 添加（TUI 内输入框：URL + 名称，v1 最简实现）、`u` 更新（重新下载快照，有差异走 diff）、`d` 删除、`enter` 切换。行内显示名称、节点数、协议摘要、上次更新时间、策略。
- 测速新增 `A` 键（当前订阅全部）。
- 鼠标支持：启用 crossterm mouse capture；点击标签页、点击代理成员选择、点击订阅行；TUI 自身配置可关闭鼠标。
- 确认页为全屏覆盖层：逐块列出差异，左右键或 `b`/`s` 切换来源（base/订阅），`enter` 确认，`Esc` 取消本次切换。

## 7. 目录与文件布局

```
~/.config/mihomo-tui/
  config.json            # TUI 自身设置（并发数、鼠标开关、全局默认策略等）
  base.yaml              # 用户拥有的基础配置
  runtime.yaml           # 生成的运行配置（每次热加载前原子重写；含 external-controller/secret，0600）
  profiles.json          # 订阅元数据（含策略记忆），0600
  subscriptions/<id>.yaml  # 各订阅原始快照，0600
```

CLI 在现有参数基础上新增 `--concurrency <N>`（默认 8）；其余现有参数保持不变。

## 8. 与现有代码的集成点

- `api.rs`：新增 `reload(config_yaml)`（封装 `PUT /configs`）；并发测速的请求封装（按请求设置超时：`--timeout` + 余量，绕开客户端现有 10 秒总超时的截断）；保留现有 client 双超时设计（流式无总超时、短请求 10s）。
- `app.rs`：新增 Profile 列表状态、确认页状态机、进行中测速任务表（含取消）；扩展 `Event`（如 `DiffProposal`、`TestProgress`、`TestCancelled`、`ReloadResult`）与 `Command`（`Reload`、`TestMany`、`CancelTests`）；`Command::TestGroup` 被池化测速取代。
- `main.rs`：事件循环与后台任务扩展；新增订阅下载任务与文件监听任务。
- `ui.rs`：新标签页、确认页覆盖层、测速进度渲染。
- 保持"UI 单线程渲染循环 + 后台任务 + 单对 channel"的现有架构不变。

## 9. 错误处理

- 导入失败 / 格式不支持：toast + 报告，不落盘半成品。
- 切换时快照缺失或损坏：提示先更新该订阅。
- 生成校验失败：不触碰控制器。
- 重载失败：回滚上一份可用配置；回滚失败：offline 状态 + 错误详情。
- 并发测速：单节点失败只标记该节点，整体继续。

## 10. 测试策略与开发安全

- 解析器：本地样例覆盖 YAML、base64、单链接、混合内容、含不支持协议的订阅。
- diff/合并：各块来源、策略预选、无差异直切、确认后生成结果断言。
- 生成器：输出 YAML 结构、原子写、校验拒绝路径。
- 重载流程：mock 控制器的成功、失败、健康检查失败触发回滚。
- 文件监听：临时目录写入触发待确认状态。
- 渲染：`TestBackend` 断言订阅页与确认页的实际文本。
- 全部测试不触网、不依赖本机 mihomo。

## 11. 留给建造者决定的部分

- YAML 库选型（`serde_yaml` 已停止维护，可在 `serde_yaml_ng`/`serde_yml` 等中选择，需说明理由）。
- 文件监听库选型（如 `notify`）及轮询兜底策略。
- 确认页与订阅页的具体布局、差异摘要的展示形式。
- 无分组订阅的默认分组生成策略（必须保证生成结果里有可用的 selector 分组）。
- TUI 内输入框组件的实现方式。
- 内部事件命名、状态机细节、模块内文件拆分。
